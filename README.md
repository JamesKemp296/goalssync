# Todo App

Minimal React + Vite + Material UI + Supabase todo app with email/password auth, multiple task lists per user, and bulk complete/incomplete on a list.

## Setup

### 1. Install

```bash
npm install
```

### 2. Supabase

1. Create a project at [supabase.com](https://supabase.com).
2. In **Settings → API**, copy your **Project URL** and **anon public** key.
3. Copy `.env.example` to `.env` and paste the values:

   ```bash
   cp .env.example .env
   ```

4. In the Supabase SQL editor, run the schema below (new projects).

5. (Optional) In **Authentication → Providers → Email**, disable "Confirm email" for faster local testing.

### 3. Run

```bash
npm run dev
```

Open http://localhost:5173. Sign up, create lists, open a list to add tasks.

## Database schema (new)

```sql
create table lists (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users default auth.uid(),
  title text not null,
  icon text not null default 'list',
  color text not null default '#92d0c8',
  pinned_at timestamptz,
  created_at timestamptz not null default now()
);

alter table lists enable row level security;

create policy "own lists" on lists
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

create table todos (
  id bigint generated by default as identity primary key,
  list_id bigint not null references lists(id) on delete cascade,
  task text not null,
  is_complete boolean not null default false,
  target_count int not null default 1 check (target_count >= 1),
  progress_count int not null default 0 check (progress_count >= 0),
  created_at timestamptz not null default now(),
  check (progress_count <= target_count)
);

alter table todos enable row level security;

create policy "todos in own lists" on todos
  for all using (
    exists (
      select 1 from lists l
      where l.id = todos.list_id and l.user_id = auth.uid()
    )
  )
  with check (
    exists (
      select 1 from lists l
      where l.id = todos.list_id and l.user_id = auth.uid()
    )
  );
```

If you already have a `lists` table without `icon`/`color`, run:

```sql
alter table lists
  add column if not exists icon text not null default 'list';

alter table lists
  add column if not exists color text not null default '#92d0c8';

alter table lists
  add column if not exists pinned_at timestamptz;
```

For multi-count tasks (tap to increment until done), run the migration in `supabase/migrations/20260529120000_todo_target_progress.sql` or:

```sql
alter table todos
  add column if not exists target_count int not null default 1 check (target_count >= 1),
  add column if not exists progress_count int not null default 0 check (progress_count >= 0);

alter table todos
  add constraint todos_progress_lte_target check (progress_count <= target_count);
```

(`list` and `#92d0c8` match defaults in `src/listIcons.ts` / `src/listColors.ts`.)

### Migrating from the older single-table `todos` (with `user_id`)

If you already created the old `todos` table with `user_id` and no `lists` table, run:

```sql
create table lists (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users default auth.uid(),
  title text not null,
  icon text not null default 'list',
  color text not null default '#92d0c8',
  pinned_at timestamptz,
  created_at timestamptz not null default now()
);

alter table lists enable row level security;
create policy "own lists" on lists
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

insert into lists (user_id, title)
select distinct user_id, 'My tasks' from todos;

alter table todos add column list_id bigint;

update todos t
set list_id = l.id
from lists l
where l.user_id = t.user_id;

alter table todos alter column list_id set not null;
alter table todos add constraint todos_list_id_fkey
  foreign key (list_id) references lists(id) on delete cascade;

drop policy if exists "own todos" on todos;
alter table todos drop column if exists user_id;

alter table todos enable row level security;
create policy "todos in own lists" on todos
  for all using (
    exists (
      select 1 from lists l
      where l.id = todos.list_id and l.user_id = auth.uid()
    )
  )
  with check (
    exists (
      select 1 from lists l
      where l.id = todos.list_id and l.user_id = auth.uid()
    )
  );
```

Adjust the migration if your old policies or column names differ.

## Routes

- `/login` — sign in / sign up
- `/` — your lists (protected)
- `/lists/:listId` — tasks in one list: mark all complete / incomplete, delete list (protected)
